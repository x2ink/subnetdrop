# 项目经验

## 文件消息操作必须覆盖持久化与实时状态

- 文件消息同时可能来自 SQLDelight 历史 Flow 和传输服务的实时 StateFlow。只删数据库会被同 ID 的实时终态重新
  补回，因此删除成功后还要从传输服务移除对应终态；活动传输必须拒绝该入口，继续走取消状态机。
- 文件转发不能复制旧 transfer ID 或终态记录，而要把仍存在的本地文件重新转换为 `LocalFile`，进入正式 offer、
  HTTP Streaming、进度与持久化链路。Android 接收文件常是 `content://`，发送前需复制到受控缓存，不能假定是普通路径。
- 首页设备项和转发目标如果表达同一种设备身份与信任状态，应复用同一 Composable；否则两个列表的状态文案、头像
  和交互层级会逐步分叉。

## 跨平台媒体缩略图

- `ContentScale.Crop` 只定义画面如何绘制，不能单独作为“不会按原始尺寸解码”的保证。图片预览必须在 Coil 请求中
  提供有界目标像素尺寸和精确缩放，让缓存键与解码结果都对应缩略图；系统打开入口再独立保留原始文件路径。
- FileKit 的 Coil 集成不是只添加依赖就会自动生效；自定义 Coil `ImageLoader` 必须注册
  `addPlatformFileSupport()`，Android 视频还必须注册 `VideoFrameDecoder.Factory()`，否则 `PlatformFile` 模型会在
  运行时落入错误占位。
- 图片解码可以由 Coil 跨平台统一，但 Coil Video 当前只覆盖 Android。桌面首帧解码应作为明确的平台适配器，且
  必须承认 JCodec 主要支持 H.264 的 MP4/QuickTime，不能把系统能播放等同于缩略图解码器一定支持。
- 发送端在传输前已经能读取源文件，但媒体消息的“预览态”代表传输完成。若直接根据路径存在显示预览，会把正在
  发送误呈现为成功；展示状态必须同时约束终态与本地文件存在性。
- 国内 Maven 镜像可能出现元数据存在但构件缺失。Gradle 从首个命中元数据的仓库解析后不会跨仓拼装同一模块，
  因此补充镜像时应按 group 做 content filter 并放在缺件镜像之前，避免无边界地改变全部依赖来源。

## 消息上下文操作与文字选择要互斥

- Android 长按同时可能触发自定义消息菜单与 Compose 原生文字选择；默认同时启用会产生手势竞争。
- 普通模式只启用长按/右键消息菜单，用户选择“部分选中”后再仅对目标正文启用 `SelectionContainer`，并暂停
  其他消息菜单，状态转换才可预测。
- 消息转发必须复用正式发送用例，不能直接调用 Transport；否则会绕过新消息持久化、重试、送达状态和加密入口。

## VPN 与局域网 Socket 路由

- 在线跟踪集合不能同时充当重试目标集合。达到离线阈值时若删除最后确认端点，而心跳又只遍历在线设备，瞬时
  启动竞态或一次 VPN 切换就会让设备永久依赖下一次组播。离线应保留已知端点继续低频单播探测，只有在线状态
  发生变化时才发布事件。
- 未验证的新地址和最后确认地址必须分开计算健康状态。伪造或过期公告的新地址探测失败不能消耗当前真实端点的
  失败次数；只有新地址完成带设备 ID 的 PING/PONG 后才能替换确认端点。
- 给组播 Socket 指定 LAN 网卡只解决“在哪个接口加入组播组”；收到候选地址后的 WebSocket 探测仍可能走系统默认
  路由。VPN 改写默认路由时，必须同时检查发现报文和单播验证/业务连接的实际出口。
- point-to-point、虚拟接口以及 `tun`、`utun`、`tap`、`ppp`、`wg` 等隧道接口不应参与局域网发现，否则公告可能
  发往 VPN 隧道，或者从不可供同网设备访问的地址发布服务。
- Android 的进程网络绑定会影响之后新建的全部 Socket。只应在局域网发现会话内绑定到 IPv4 Wi-Fi，并保存、恢复
  原绑定；恢复失败要清回系统默认网络，不能把进程永久留在已失效的 Wi-Fi Network。
- 应用级选路无法绕过 VPN kill switch、Android lockdown、AP 隔离或防火墙。此类限制必须显式告知用户开启 VPN
  的“允许局域网访问”，不能把编译成功宣称为所有 VPN 均已兼容。

## 跨平台文字选择

- 仅需要系统标准的选择与复制行为时，使用 Compose `SelectionContainer` 即可同时覆盖 Android 长按工具栏和桌面
  指针选择/复制快捷键，不需要分别调用 Android ClipboardManager 和 AWT Clipboard。
- 选择范围应缩到消息正文；把整个时间线或气泡列放进同一个容器，会把送达状态、失败提示甚至相邻消息意外复制。

## 双端独立的文件大小策略

- 文件大小上限既是本机发送策略，也是本机接收资源保护策略，不能只在文件选择后校验一次；发送端应尽早失败，
  接收端必须在 offer 阶段再次按自己的设置校验，且不能信任对端配置。
- 用户设置可以放宽产品默认值，但不能替代协议绝对上限。领域模型约束合法区间，持久化适配器验证写入值，网络层
  消费只读 StateFlow，避免 UI、存储和协议各维护一份不同常量。
- 超大文件边界测试应使用稀疏文件，只验证元数据和拒绝路径，不分配或读取同等体积的数据。

## 多文件并行与双端进度

- 多选不应等同于无限并发。先为全部文件创建可见的排队消息，再用进程级 Semaphore 控制真实网络任务，既能让
  用户确认选择结果，也能避免多个批次绕过各自的局部并发限制。
- 批次任务需要 supervisor 语义：一个文件失败只影响自身，但批次完成时仍要汇总失败，不能让 UI 误报全部成功。
- 写入本机 HTTP/WebSocket channel 成功只代表数据进入发送管线，不能作为对端已接收进度；双端进度应以接收端
  已写入目标 sink 的累计字节为唯一事实。
- 进度同步与流量控制应解耦：接收端通过控制 WebSocket 异步签名上报累计值，文件正文依靠 HTTP/TCP 背压持续
  流动，不要再用应用层 checkpoint 把连续数据面改成停等协议。
- 数据面的一次性 Token 不能单独承担身份认证。HTTP 请求还应签名绑定协议版本、双方身份、传输 ID、Token 和
  `Content-Length`，并在开始消费正文前验证过期、重用和控制连接状态。
- 接收文件写入和 SHA-256 不能在全局传输 Mutex 内执行。每个文件用自己的 I/O Mutex 保证顺序，全局锁只保护
  session map 和状态提交，否则名义上的三文件并行会在接收端重新串行。
- 取消、完成和异常可能并发到达，终态更新必须在同一互斥区里检查并变更，避免已经完成的文件被迟到异常覆盖为失败。

## IME 与聊天列表底部锚定

- `imePadding` 只能保证输入区避开键盘；普通正向 `LazyColumn` 在 viewport 变小时会保留滚动位置，不能保证最后
  一项仍然可见。
- 聊天时间线要在键盘动画和窗口缩放中稳定贴住输入区，应使用最新项位于索引 0 的 `reverseLayout`。新消息只需
  滚动到 0，列表高度变化会保持底部锚点，不依赖猜测键盘动画时长。
- reverse layout 只会保持当前锚点；如果用户停在历史消息处，键盘弹出不会自动回到最新消息。输入框获得焦点时
  还需要显式滚动到 0，然后再让底部锚定负责后续 IME 尺寸变化。

## Edge-to-edge 顶部颜色与导航动效

- 系统状态栏设为透明后，它显示的不是顶部栏自身颜色，而是系统 inset 后面的根容器颜色。要让二者完全一致，
  Scaffold 的系统栏承载层与聊天 Header 必须使用同一个 color token，页面内容背景应从 inset 内部再绘制。
- Material3 `Surface` 的 `tonalElevation` 会在 `surface` 上叠加主题色；即使两个区域声明同一个 token，也可能呈现
  蓝白色差。要求像素同色的系统栏与顶部栏不能只比较 `color` 参数，还要消除 tonal overlay。
- Navigation3 的返回默认使用 pop transition。即时通信页面如果产品要求立即返回，就应同时关闭普通 pop 和
  predictive-pop transform；只缩短动画仍会保留“页面关闭”的视觉语义。

## Navigation3 退出条目的状态一致性

- Navigation3 从 back stack 移除页面后，退出条目仍可能在同一帧参与组合。若此时 selection 驱动的消息 Flow
  主动发出空列表，而文件传输 StateFlow 仍保留数据，聊天时间线就会瞬间退化成“只剩文件消息”。
- 未选择会话时应切换到不发值的 `emptyFlow`，让退出条目保留最后一份文字消息；新会话渲染还必须按
  conversation ID 过滤，避免保留值造成跨会话闪烁。
- 页面转场期间可能同时绘制进入与退出内容，因此聊天页根节点必须绘制完整不透明背景。关闭动画不能替代正确的
  绘制隔离和状态一致性。
- 产品要求“无卡片阴影”时，要同时检查 `shadowElevation` 和 `tonalElevation`；后者虽然不是物理阴影，也会改变
  Surface 的视觉层级。

## 暂存区自动提交 Skill 的授权语义

- 显式调用 `$staged-auto-commit` 本身就是提交当前暂存区的授权，不应退化为只输出 message，也不应再次询问确认。
- 用户已经用暂存区表达了提交边界，Skill 不应擅自 `git add`、拆分或混入工作区内容；提交失败也不能用
  `--no-verify` 绕过 hook。
- “只查看 commit message”仍是只读请求；仅在调用自动提交 Skill 或明确要求提交时执行 `git commit`。
- Skill 行为或名称改变时同时检查目录名、frontmatter、`agents/openai.yaml`、根 `AGENTS.md` 和 README，避免旧入口
  或旧授权语义残留。

## Compose 消息卡片测量

- `heightIn(min = ...)` 只保证容器高度，不会自动把子项居中；气泡正文需要明确的对齐容器，否则单行文字会偏上。
- 自适应卡片不能同时保留固定 `minWidth`、内部 `fillMaxWidth` 和填满型 `weight`，其中任一项都可能把短内容撑到
  最大可用宽度。应由内容的 intrinsic width 决定实际宽度，只保留防止桌面端过宽的最大值。

## 文件接收策略与平台体验

- “默认自动接收、可选逐文件确认”是传输策略，不是对话框显隐选项；必须持久化到领域端口，并由网络层处理每个
  offer 时读取，才能保证 UI 与协议行为一致。
- 自定义 Android SAF 目录不能只保存 `content://` 字符串，还要在选择时获取持久化权限；优先调用 FileKit 的
  bookmark API，不重复实现 ContentResolver 权限细节。
- edge-to-edge 同时包含状态栏、手势/三键导航栏和内容 inset。仅设置透明色不一定消除 Android 10+ 三键导航的
  对比度遮罩，需要把 `isNavigationBarContrastEnforced` 纳入验证。

## 聊天时间线与 IME 布局

- 文件传输如果属于聊天语义，就必须作为带稳定 key 和时间戳的时间线 item 与文字共同滚动；不要在输入框上方
  再放一个独立的固定高度传输面板，否则文件不具备消息的位置和方向语义。
- 发送/已读状态不应放进文字气泡的内容容器，它会参与气泡宽高测量；状态应作为气泡下方的同方向附属行。
- edge-to-edge 的聊天输入栏不能只在输入栏内部叠加 `imePadding`。先消费 Scaffold 已应用的系统栏 inset，再由
  页面外层处理 IME，并配合 Activity `adjustResize`，才能避免导航栏与键盘 inset 双算。

## 项目级 Codex Skill 的发现目录

- 项目内需要自动发现或通过 `$skill-name` 调用的 Skill 必须放在 `.agents/skills/<skill-name>/`，不能使用普通
  `skills/` 目录替代。
- 创建后同时检查 `SKILL.md`、`agents/openai.yaml` 和 `AGENTS.md` 中的路径，运行 Skill validator，并确认
  `policy.allow_implicit_invocation` 符合用户要求。
- 涉及已有暂存内容时，先区分 index 与 working tree；修正文件位置不等于已经更新暂存区，未经提交计划确认
  不擅自执行 `git add`。

## 个人 GitHub 项目的提交格式

- 本仓库使用标准 Conventional Commit：`type(scope): subject`。
- 不从外部模板继承任务号、日期后缀或额外 footer；修改提交生成 Skill、共享 hook 和本地激活副本时
  必须同时核对，避免清理后再次生成。

## Android 交互与启动性能验证

- 仅用状态容器单元测试和 Android 编译不能证明真机触摸链路可用；用户报告真机交互故障时，必须安装当前 APK，
  通过实际点击前后截图验证页面内容和选中状态都发生变化。
- 启动流程包含多个异步系统组件时，`Starting` 必须暴露具体阶段或留下等价诊断证据，不能根据代码阅读猜测阻塞点。
- Navigation3 的 `entryProvider` 会按 back stack 保存 `NavEntry`；不能在 entry 内容闭包中直接捕获会整体替换的
  UI 快照，应捕获稳定的 `State` 并在 entry 组合内部读取最新值，否则运行时横幅和页面切换会一起停在旧状态。
- 调试器断点会暂停主线程并可能触发 OEM 的输入超时 ANR；断点日志只能证明回调命中，判断真实 ANR 必须在
  断开调试器后重新冷启动复现。
